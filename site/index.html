ARCHITECTURE & GARANTIES FORMELLEMENT VÉRIFIÉES — WORKSPACE RUST 6 CRATES

Les 8 Piliers Fondamentaux du Langage knr

Conçu dès le premier octet pour être généré, vérifié, exploré et compilé en quelques microsecondes par des agents IA comme par des ingénieurs systèmes.

01 / PROPRIÉTÉ LINÉAIRE

Mutation In-Place sans GC

Les types linéaires (buf, vec, map, chan, struct) ont un propriétaire unique. struct_set, vec_push et map_set mutent la mémoire sur place en O(1) sans jamais cloner ni solliciter de Garbage Collector.

02 / JUGE STATIQUE (< 100 µs)

Diagnostics JSON & fix_hint

4 passes (SSA, Alive/Moved, Types, Effets). En cas de UseAfterMove ou LinearLeak, knr-verify renvoie l'état exact des registres vivants et l'instruction corrective dans fix_hint.

03 / SYSTÈME D'EFFETS

Net, Ui, Hw & Async isolés

Serveur HTTP Tokio, moteur VDOM HTML (qui génère cette page !) et buffers matériels alignés sur 64 octets pour SIMD XOR et DMA. Toute fonction pure a l'interdiction formelle d'appeler un syscall.

04 / MULTI-CIBLES & KNIR

VM Gas, Cranelift & WASM

Bijection 1:1 entre texte .ssa et bytecode 64-bit .knrbin. Oracle VM avec compteur de cycles anti-boucle infinie et compilation native ELF (Cranelift) ou WebAssembly (.wasm).

05 / TOPOLOGIE MULTI-FICHIERS

Séparation .ssa.schema vs .ssa

Le compilateur impose l'architecture du projet : les schémas de données vivent exclusivement dans des fichiers .ssa.schema et les fonctions dans des fichiers .ssa avec résolution d'imports en diamant.

06 / EXPLORATION IA (KNR EXPLORE)

Ripgrep Sémantique AST One-Shot

Cartographie instantanée d'un projet multi-fichiers : --symbol, --callers, --callees, --effects, --orphans et export en format IA compact, JSON déterministe ou diagramme Mermaid.

07 / UI DÉCLARATIVE & PONT WASM

Zéro Script JS Inline dans le Code

Les composants UI déclarent uniquement action (champ 3) et target (champ 4) sur struct[Leaf]. UiPlatform injecte automatiquement le pont hybride SSR HTTP + réducteur WebAssembly (site.wasm).

08 / HARDWARE & SIMD 64 OCTETS

Alignement Cache-Line & AVX-512

Chaque buf_alloc garantit un alignement matériel strict sur 64 octets vérifié à l'exécution, permettant des opérations SIMD XOR sans copie et une interopérabilité C-ABI directe.

SPÉCIFICATION ISA v1.0 — BIJECTION 1:1 TEXTE (.SSA) <-> BYTECODE 64-BIT (.KNRBIN)

Les 29 Opcodes Orthogonaux & 3 Terminateurs de Blocs

Chaque instruction knr est encodée dans un mot fixe de 64 bits [opcode:8 | type_tag:8 | dst:16 | src0:16 | src1:16]. Aucune ambiguïté syntaxique pour les LLM, décodage O(1) et vérification statique complète en 4 passes.

FAMILLE 01 • OPCODES 0x01..0x04 (COPY)

Constantes Typées & Pool

0x01 const_i64  %d = const_i64 42
0x02 const_f64  %d = const_f64 3.5
0x03 const_bool %d = const_bool true
0x04 const_str  %d = const_str "knr"
FAMILLE 02 • OPCODES 0x05..0x0E (ALU)

Arithmétique & Bitwise

0x05 add     0x06 sub     0x07 mul
0x08 div     0x09 rem     0x0A bit_and
0x0B bit_or  0x0C bit_xor 0x0D shl
0x0E shr     (i64 / f64 / bitwise)
FAMILLE 03 • OPCODES 0x0F..0x12 & CFG

Comparaisons & Terminateurs

0x0F cmp_eq  0x10 cmp_ne
0x11 cmp_lt  0x12 cmp_gt  (-> bool)
CFG: br bbX | br_if %c bbT bbF | ret %v
FAMILLE 04 • OPCODES 0x13..0x17 (LINEAR BUF)

Buffers Linéaires Alignés 64B

0x13 buf_alloc %sz   -> buf (Alive)
0x14 buf_free  %b    -> consomme %b
0x15 buf_read  %b %i -> i64 (Borrow)
0x16 buf_write %b %i %v -> buf (Move)
0x17 buf_slice %b %s %e -> buf (Move)
FAMILLE 05 • OPCODES 0x18..0x1D (COLLECTIONS)

Vecteurs & Maps In-Place

0x18 vec_new T       0x1B map_new K V
0x19 vec_push %v %x  0x1C map_set %m %k %v
0x1A vec_get  %v %i  0x1D map_get %m %k
(Mutation linéaire sans allocation GC)
FAMILLE 06 • SCHÉMAS, CANAUX, SYSCALL & CALL

Structs, Async, Effets & Call

chan_new / chan_send / chan_recv
struct_new S / struct_get / struct_set
syscall Eff "op" %args... | free %r
call fn_name %arg0 %arg1 ... (0x1E)

fn fib(%0: i64) -> i64 {

EXEMPLE 7 — BUFFERS LINÉAIRES ALIGNÉS 64 OCTETS, SLICE & LIBÉRATION EXPLICITE
fn process_packet() -> i64 {
bb0:
    %0 = const_i64 64
    %1 = buf_alloc %0          // %1: buf (Alive, aligné 64B)
    %2 = const_i64 0
    %3 = const_i64 1337
    %4 = buf_write %1 %2 %3    // %1 -> Moved, %4 -> Alive
    %5 = const_i64 16
    %6 = buf_slice %4 %2 %5    // %4 -> Moved, %6 -> Alive
    %7 = buf_read %6 %2        // Borrow lecture sans consommer %6
    buf_free %6                // %6 -> Consommé (0 fuite mémoire)
    ret %7
}
EXEMPLE 8 — COLLECTIONS LINÉAIRES VEC[I64] & MAP[STR, I64] IN-PLACE
fn index_scores() -> i64 {
bb0:

    %1 = const_str "alice"
